## INTRODUCTION

For 2D physical simulation programs, it is always important to have a discretization scheme, for which we have to obtain a mesh and its numerical data. Many meshing programs generate meshes for us, providing a text file containing nodes and their positions, as well as edges, cells, and the nodes that form them. However, for many physical schemes, we need more information than that, such as connectivity, ghost cells (for interpolation enforcement), topology, geometric and numerical data, and so forth.

---

## WHAT DOES THIS PROGRAM EXACTLY OBTAIN?

This program creates four arrays of structures: one for nodes, one for edges, one for domain triangles, and another for ghost triangles. Each struct has its own data:

### Node Struct
- **Node ID**
- **Position** $(x, y)$

### Edge Struct
- **Edge ID**
- **Nodes IDs**
- **Length**
- **IDs of triangles that share it**
- **Midpoint** $(x, y)$
- **Distances** between the midpoint and the centroids of the triangles that share it
- **Geometric weights**

### Domain Triangle Struct
- **Triangle ID**
- **Area**
- **Edges IDs**
- **Nodes IDs**
- **IDs of neighbor triangles**
- **Centroid** $(x, y)$
- **Unit normal vectors**
- **Vectors** from self-centroid to neighbors' centroids
- **Vectors** from centroid to self-edges' midpoints

### Ghost Triangles Struct
- **Triangle ID**
- **Type** (from boundary)
- **Inner triangle ID**
- **Centroid** $(x, y)$

> **Note:** Since the ghost triangles array is created after obtaining the domain triangles data, the ghost cell IDs start directly after the last domain triangle ID.

These arrays are also saved within a parent object named `MeshData`, which also contains general information:
- Domain triangles number
- Ghost cells number 
- Boundary edges number
- Edges number
- Nodes number
- Unstructured maps used for data extraction

Finally, this information is written into five `.txt` files in the `output/` directory. If you need this information for a numerical solver creation u can obtain the information directly from the struct, ignoring the `.txt` files.

---

## WHAT DOES THIS PROGRAM NEED?

This preprocessor is designed to read 2D triangular non-structured `.msh` files generated by **Gmsh**. The required text structure follows the **Gmsh ASCII 2.2** format:

```text
$Nodes
nodes_number
ID  x   y   z
...
$EndNodes
$Elements
number_of_elements
boundary_edge_ID  1   2   boundary_type   1   node_1_ID   node_2_ID  
...
triangle_ID  2   2   1   3   node_1_ID   node_2_ID   node_3_ID
...
$EndElements
```
